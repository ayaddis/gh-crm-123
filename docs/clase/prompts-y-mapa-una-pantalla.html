G1Claude.ai Chat · paso 1.1 · prompt completo

## El proyecto Necesito tu ayuda para preparar las instrucciones de un proyecto: un CRM minimalista y simplificado, de funcionalidad estándar y con opciones estrictamente básicas pero necesarias, que voy a construir con herramientas de IA de Claude. No tengo perfil técnico. Está destinado a un equipo comercial pequeño, con dos aplicaciones web: 1) Una aplicación web de escritorio para la gestión diaria de los vendedores. 2) Una PWA para el supervisor. ## Restricciones que debe seguir estrictamente toda la documentación 1. El diseño y el desarrollo deben ser estándar, simplificados, minimalistas y funcionales, con opciones estrictamente básicas y necesarias, siguiendo buenas prácticas de diseño y desarrollo. 2. Prohibido pedir o guardar identificadores personales (DPI, NIT, DNI, pasaporte). El teléfono se usará como identificador del cliente. 3. Roles del CRM: Vendedor y Supervisor, con usuario y contraseña; 10 vendedores y 2 supervisores. El Supervisor debe tener todos los accesos de administrador. 4. Los datos se almacenarán en Supabase. 5. El proyecto de Claude Code Web se guardará en GitHub. 6. El despliegue de GitHub hacia Vercel se realizará manualmente. 7. El resumen matutino se activa en la PWA para enviar un correo desde n8n vía Resend. 8. Automatizaciones en n8n: resumen matutino por correo a cada vendedor. ## Configuración a utilizar en todo el proyecto 1) Nombre de marca: CRM-123 2) Una rama para los fuentes de Claude Code Web, con dos carpetas una para sitio Web y otra para PWA, el nombre de la rama es : gh-crm-123 3) Nombre de la base de datos en el almacén de Supabase: dbcrm123 4) Organización de Supabase: Org CRM 123 5) El flujo n8n para el resumen matutino llámalo: WF-CRM123 6) El correo originador para Resend es onboarding@resend.dev ## Cómo quiero que trabajemos Entrevístame por rondas temáticas: máximo 5 preguntas por ronda y máximo 6 rondas. Antes de cada ronda, dime en una línea qué vamos a decidir. - Confirma al inicio el giro del negocio, el país de operación y la moneda. - Usa lenguaje de negocio. Si necesitas un dato técnico, explica en una línea qué implica cada opción y recomiéndame una que sea simple pero segura. - Si la decisión es de bajo riesgo, propón un valor por defecto y solo pídeme confirmarlo. - Si mi respuesta abre una decisión nueva, agrégala a una ronda posterior. - Cierra cada ronda con un resumen acumulado de lo decidido. - Para las piezas del stack que aún faltan, propónmelas tú con una justificación breve y déjame aprobarlas. ## Cinco entregables que debes generar Al terminar la entrevista, y no antes, genera los documentos por separado: DESIGN_BRIEF.md, TECHNICAL_SPEC.md, CLAUDE.md, BUILD_PLAN.md, SCRIPTS-SQL.md con las siguientes especificaciones para cada uno: **`DESIGN_BRIEF.md`** para Claude Design: pantallas, información y jerarquía de cada una, estados (vacía, cargando, error, proceso en ejecución), flujos y dirección visual. El escritorio es denso y operativo; el móvil es de consulta rápida. Sin código ni base de datos. Debe respetar estrictamente la estructura de base de datos que se trasladará en SCRIPTS-SQL.md al momento del diseño, sin realizar cambios. **`TECHNICAL_SPEC.md`** para Claude Code Web: modelo de datos, reglas de seguridad por fila, endpoints, cómo se protege paso a paso el disparo manual de la automatización del flujo de n8n, y variables de entorno. Debe respetar estrictamente la estructura de base de datos que se trasladará en SCRIPTS-SQL.md al momento del diseño, sin realizar cambios. **`CLAUDE.md`**: el contrato para Claude Code Web, con las siguientes reglas de seguridad ## Seguridad, lo innegociable Estas reglas no se relajan por comodidad ni por prisa. Todas deben cumplirse en los comandos de la base de datos. - **RLS activa en todas las tablas**, incluidas configuración y auditoría. Ninguna excepción. - **Ninguna política de `DELETE`.** No hay borrado físico, solo archivado lógico. Nunca uses la palabra "eliminar" en la interfaz. - **`activities` y `audit_log` son solo de inserción.** Sin políticas de `UPDATE` ni `DELETE` para nadie, incluido el supervisor. - **Toda política de `UPDATE` lleva `with check`**, no solo `using`. Sin él, un vendedor cambia `owner_id` y se queda con la oportunidad de otro. - **Ninguna política con condición `true`**, salvo el `select` de `settings`. - **Todas las vistas con `security_invoker = true`.** Una vista sin esto filtra los datos de todo el equipo a cualquier vendedor. - **Toda función `security definer` fija `search_path = public`.** - **`SUPABASE_SERVICE_ROLE_KEY` nunca sale del servidor.** Solo en Route Handlers y Server Actions. Jamás en un componente cliente, ni siquiera importado sin usar. - **Los secretos se comparan con `crypto.timingSafeEqual`**, nunca con `===`. - **El rol se lee de la tabla `profiles`**, nunca de un JWT ni de nada que venga del cliente. - **n8n nunca toca Postgres.** Todo pasa por los endpoints `/api/n8n/*` de la aplicación. **`BUILD_PLAN.md`**: un plan de 4 hitos. Al inicio de cada hito, informa las variables de entorno que necesitan las aplicaciones para toda su funcionalidad, explica el procedimiento para obtener sus valores y verifica que estén configuradas en los aplicativos. Si el humano tiene que actualizarlas, avísalo al final del hito, antes de las pruebas de funcionalidad. ***Para que Claude.ai Chat genere todas las instrucciones de creación, pruebas y validación de la base de datos con el conector MCP de Supabase (que se le proporcionará cuando el humano ejecute este primer HITO en otra conversación de Claude.ai Chat), toma en cuenta toda la documentación que estamos construyendo: `CLAUDE.md`, `TECHNICAL_SPEC.md` y, especialmente, `SCRIPTS-SQL.md`, que contendrá toda la estructura oficial de la base de datos y las pruebas para confirmar su correcta creación. ### Hito 1 - Base de datos: **Qué construye:** el script para la base de datos; entrégalo. Nada de interfaz. ***Para que Claude Code Web construya el plan de despliegue en 3 hitos, toma en cuenta `CLAUDE.md` y `TECHNICAL_SPEC.md` para cada uno. En cada hito, indica que NO puede avanzar al siguiente hasta recibir la confirmación del humano. Por cada hito, entrega el procedimiento a seguir y las variables que deben crearse en Vercel. ### Hito 2 - Entrar y desplegar **Qué construye:** del proyecto, solo el ingreso, el armazón de navegación y el tablero del día vacío. ### Hito 3 - Núcleo comercial **Qué construye:** agrega a la funcionalidad existente lo que un vendedor usa todos los días. ### Hito 4 - Supervisión y una automatización **Qué construye:** agrega a la funcionalidad existente el panel del equipo y el flujo JSON de n8n del spec (resumen matutino) para importarlo manualmente en n8n Cloud. **`SCRIPTS-SQL.md`**: genera la estructura de base de datos de este proyecto, que será la oficial para todos los documentos, y todos los scripts SQL para construirla. Se usará para lo siguiente: 1) Que Claude.ai Chat la utilice para crear toda la estructura de base de datos en el almacén de Supabase y, además, compruebe toda la estructura: llaves, índices, roles, políticas y todas las condiciones de integridad o relación. 2) Que Claude Design la tome como referencia en el diseño. 3) Que Claude Code Web la utilice como estructura estricta del almacén de datos. Después de entregar los cinco entregables, ya no realices nada más, pregunta si puedes iniciar con el Hito 1 para creación de base de datos y espera confirmación.

Para qué sirvió: describió el proyecto, fijó las restricciones y la configuración, y pidió una entrevista por rondas. Al final generó cinco documentos: DESIGN_BRIEF, TECHNICAL_SPEC, CLAUDE, BUILD_PLAN y SCRIPTS-SQL. Aquí está el origen de los documentos de reglas. Validación contra la guía del profesor

Comparé la guía (63 páginas) con lo que se hizo en esta conversación. La cadena de trabajo es la misma. Cambian los detalles, porque los documentos de reglas de este ejercicio son otra versión de los que usa la guía.

Coincide

  • Prompts 1 y 2: el texto es idéntico a los pasos 2.14 y 3.7.
  • Cadena: Claude.ai Chat, Claude Design y Claude Code Web, en ese orden.
  • Cuatro hitos, cada uno con confirmación escrita antes de avanzar.
  • Dos proyectos en Vercel (web y pwa), un flujo de n8n a las 7:30 de lunes a viernes y remitente onboarding@resend.dev.
  • El resumen llegó solo el martes y el miércoles a las 7:30.
  • El manual de usuario del paso 4.31 ya se generó, en Markdown y en PDF.

Difiere

  • Pruebas de la guía con euros y teléfono +34. Este ejercicio usa pesos y 10 dígitos.
  • Variables: la guía usa N8N_SHARED_SECRET y N8N_WEBHOOK_MORNING_DIGEST_URL. Aquí fueron N8N_WEBHOOK_URL, N8N_WEBHOOK_SECRET y N8N_API_SECRET.
  • Seguridad del disparo: la guía usa firma y nonce. Aquí, dos secretos distintos y una espera de 120 segundos (la guía pide 10 minutos).
  • Archivo del flujo: n8n/morning-digest.json en la guía y n8n/WF-CRM123.json aquí.
  • Nombres en Vercel: gh-crm-123-web y -pwa en la guía; crm-123-web y -pwa aquí.
  • Llaves de Supabase: la guía usa las "Legacy". Aquí se usaron las nuevas (publishable y secret).
  • El Hito 4 de este ejercicio tuvo 11 pruebas. La guía lista 29.

Falta

  • La prueba 29 de la guía: que no llegue nada en fin de semana. Se puede comprobar este sábado 21 o domingo 22.
  • El prompt "entrega el JSON para n8n primero e inicia el Hito 4" (paso 4.18) no se usó. Aquí el flujo salió dentro del Hito 4.
Corrección a lo que dije antes: el origen de los documentos de reglas sí está documentado. Los generó Claude.ai Chat en la fase 1 de la guía (prompt G1). El README.handoff lo generó Claude Design (prompt G5).
